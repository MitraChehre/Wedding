# Wedding Planning Workspace

This repository is the canonical read-and-write workspace for planning our destination wedding. No destination country has been selected: Armenia is the leading hypothesis and Turkey is one candidate.

GitHub is not only reference material. Before substantive work, the assistant reads the relevant files; after substantive work, it writes back every durable decision, requirement, plan, research finding, correction, priority, task, and useful interaction outcome. Chat alone is not durable project storage.

## Current status

- High-level requirements interview: complete.
- Current phase: destination selection and planning foundations.
- Active parallel streams: destination comparison, guest list, budget feasibility, and planner-ready requirements brief.
- Operational spreadsheet: the private Google Sheet `Plan` holds current to-dos, personal guest-list data, and working budget data; GitHub retains durable project knowledge and the full roadmap.
- Target window: September–December 2027.
- Working budget: about €30,000, subject to evidence-based testing.
- Invitations: about 200; attendance scenario up to about 150 and likely lower.
- Next decision gate: destination country/region after access and budget evidence.

## Start here

1. Read AGENTS.md for mandatory operating and write-back rules.
2. Read MEMORY.md for the complete durable requirements and preferences.
3. Read PROJECT.md for the current brief, dependencies, and full roadmap.
4. Read TASKS.md for active priorities and next questions.
5. Read DECISIONS.md before reopening settled or corrected matters.
6. Use vendors/ for dated research and comparisons.

## Repository map

- AGENTS.md — assistant instructions and persistence protocol
- MEMORY.md — durable facts, preferences, constraints, and outcomes
- PROJECT.md — current brief and phased parallel roadmap
- TASKS.md — prioritized queue, dependencies, gates, and questions
- DECISIONS.md — confirmed, corrected, and superseded decisions
- vendors/ — vendor and market research with evidence

## Core working principle

Plan proactively across parallel workstreams, but make decisions in dependency order. Keep facts, assumptions, recommendations, and pending choices distinct. Correct stale content in place, avoid duplicate sources of truth, and commit completed durable changes directly to main by default.
